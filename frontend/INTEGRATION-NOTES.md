# 프론트엔드 API 호환 수정본

원본: 사용자가 첨부한 WearCare-Mate-frontend.zip의 frontend 폴더.
GitHub 및 AWS에는 반영하지 않은 검토용 소스입니다.

## 변경 사항

- 정상 판정, 데이터 부족, 가이드 생성 실패, 실제 생성, 예시 가이드의 배지 구분.
- 가이드 기준일 및 출력 규칙 검사 경고 표시.
- 빈 수면/심박 배열에서 Infinity/-Infinity 및 0으로 잘못 표시하지 않음.
- delta=null이면 비교 데이터 없음으로 표시.
- 기기, 알림, 가이드 이력의 빈 목록 안내.
- 미연결 실시간 동기화 및 SageMaker 표시를 기록 조회/활동량 기준선으로 정정.
- 대시보드에 분석 기준일과 날짜별 판정 범위 표시.
- 가이드 재조회 오류 시 기존 대시보드를 유지하며 오류와 재시도 버튼 표시.
- API 기본 주소 끝의 슬래시 제거.

## 검증

- Jest 테스트 8개 통과: 6개 메뉴 전환, 실제 응답의 빈 배열, nullable delta,
  가이드 상태 및 경고, 재조회 실패 후 복구 가능 여부.
- 프로덕션 빌드 Compiled successfully.
- 실제 프론트엔드 브라우저 -> 공개 API 통합 검증 및 시각 검수는 아직 하지 않음.

## 사용 방법

ZIP에는 frontend/ 폴더가 있습니다. 같은 브랜치의 기존 frontend/와 비교하여 반영하세요.
node_modules, build, .env 및 다른 파트의 코드는 포함하지 않았습니다.
의존성 변경은 없습니다. 설치 후 npm start 또는 npm run build로 실행합니다.

실제 API 연결 시 .env.example을 .env로 복사하고 시작 프로세스를 재시작하거나 다시 빌드합니다.
현재 예시 주소의 공개 API는 mock 응답을 반환합니다.
실제 데이터/AI 응답을 확인한 것은 API Gateway가 연결되지 않은 별도 테스트 함수입니다.
프론트엔드에서 해당 테스트 함수를 직접 호출하도록 변경하지 마세요.

## 팀에서 확인할 사항

1. 프론트엔드 담당자에게 배포 origin 또는 로컬 실행 주소를 받아 CORS에 등록.
2. 실제 데이터 공개 전 백엔드 인증/인가 및 데이터 접근 범위 확정.
3. 새 응답의 analysis, guide status/warnings, null delta를 최종 명세에 반영.
4. 그래프의 false는 해당 날짜의 정상 판정을 보장하지 않음. analysis.evaluatedDates의 날짜만 평가됨.
5. 프로필은 기존처럼 브라우저에만 저장. 기기 연결 버튼 및 SNS/이력 저장은 아직 실제 연동 아님.
6. 가이드 재조회는 정상일에 생성을 강제하지 않음. 생성 요청이 필요할 때 비용/지연 검증 필요.

이번 수정본의 검증은 mock 및 실제 API 응답 형태를 재현한 테스트 기준이며,
전체 서비스 연결 완료를 의미하지 않습니다.
